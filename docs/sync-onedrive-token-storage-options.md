# J-Flow OneDrive Token 存储方案对比

## 文档定位

这份文档用于在 OneDrive OAuth POC 开始前，先把 token 存储方案收口。

目标不是立刻选型实现，而是先明确：

- POC 阶段推荐什么
- 正式阶段推荐什么
- 各自风险是什么
- 是否影响 macOS / Windows 打包

---

## 一、共同原则

无论采用哪种方案，都必须满足：

- access token / refresh token 是本机敏感授权信息
- 不写入同步目录
- 不写入 `items / tombstones`
- 不进入 JSON 备份
- 不跨设备同步
- renderer 不直接持久化 token

---

## 二、方案 A：`keytar`

### 方案说明

使用系统凭据存储封装，把 token 交给：

- macOS Keychain
- Windows Credential Manager

### 优点

- 更接近正式应用的敏感信息存储方式
- 用户授权信息和普通业务数据隔离更清楚
- 平台语义更符合“账号凭据”

### 风险 / 缺点

- 通常涉及原生模块
- 会增加本地开发环境和打包链路复杂度
- 可能带来：
  - Node / Electron ABI 兼容问题
  - 重建问题
  - macOS / Windows 打包额外排查成本

### 对打包的影响

- 对 macOS / Windows 打包有一定影响
- 尤其在 Electron 升级、架构切换、签名或 CI 构建时，维护成本较高

### 适用阶段

- 更适合正式阶段

---

## 三、方案 B：Electron `safeStorage` + 本机隔离文件

### 方案说明

思路是：

- token 内容先经 `Electron safeStorage` 加密
- 再写入本机专用隔离配置文件
- 配置文件只保存在当前设备

### 优点

- 不依赖额外原生凭据模块时，工程集成通常更轻
- 仍然比明文文件安全得多
- 容易和 Electron main process 的本地配置管理结合

### 风险 / 缺点

- 仍然需要自己管理：
  - 文件位置
  - 读写错误恢复
  - token 生命周期
  - 损坏恢复策略
- 安全边界通常不如直接使用系统凭据库那样“语义天然”

### 对打包的影响

- 相比 `keytar`，通常对 macOS / Windows 打包影响更小
- 更像 Electron 内建能力 + 普通本地文件管理

### 适用阶段

- 适合作为 POC 阶段推荐方案
- 也可作为正式阶段备选方案

---

## 四、方案 C：POC 临时明文 / 隔离存储

### 方案说明

把 token 仅保存在本机某个隔离配置文件中，不加密或只做非常轻的隔离。

### 优点

- 实现最快
- 最适合极早期验证“授权流程能不能跑通”

### 风险 / 缺点

- 安全风险最高
- 极易被误用到可分发版本
- 开发期也容易因为日志、调试文件、备份文件而泄露凭据

### 对打包的影响

- 对打包本身影响最小
- 但对安全审查和后续收口影响最大

### 适用阶段

- 只适合非常短期、不可分发的本机实验
- 不建议作为可提交主线方案

---

## 五、推荐结论

### 1. POC 阶段推荐

推荐：

- `Electron safeStorage + 本机隔离文件`

原因：

- 比明文安全
- 比 `keytar` 更轻量
- 更适合先验证：
  - OAuth 回调
  - token refresh
  - App Folder metadata 读写

### 2. 正式阶段推荐

推荐：

- 优先评估 `keytar` 或等价系统凭据存储方案

原因：

- 正式阶段更需要把授权凭据和普通本地配置彻底分层
- 对用户可信度和长期维护更有利

### 3. 开发期兜底方案

如果为了极小 POC 需要临时加速，可以短期使用：

- 明文 / 轻隔离存储

但要求：

- 只限本机临时验证
- 不进入主分支默认方案
- 不进入可分发包

---

## 六、各方案对比结论

| 方案 | POC 推荐度 | 正式推荐度 | 安全性 | 打包影响 |
| --- | --- | --- | --- | --- |
| `keytar` | 中 | 高 | 高 | 中到高 |
| `safeStorage + 本机隔离文件` | 高 | 中 | 中到较高 | 低到中 |
| 明文 / 轻隔离文件 | 低 | 低 | 低 | 低 |

---

## 七、当前建议

当前建议先这样收口：

1. OneDrive OAuth POC 阶段
   - 采用 `safeStorage + 本机隔离文件`
2. 真正进入可分发桌面版本前
   - 再决定是否升级为 `keytar` / 系统凭据存储
3. 明文 token 存储
   - 只作为不得已的短期实验手段
   - 不写入正式规划主线
